5.##Название уязвимости: Раскрытие чувствительных данных через открытую FTP-директорию (Confidential Document)

* **Категория OWASP Top 10:** A01:2021-Sensitive Data Exposure / Security Misconfiguration

### Описание
В приложении обнаружена небезопасная конфигурация веб-сервера, оставляющая публично доступной внутреннюю директорию `/ftp`. Разработчики оставили конфиденциальные документы компании в этой папке без надлежащего контроля доступа, что позволяет любому неавторизованному пользователю просматривать и скачивать файлы методом прямого перебора URL-адресов (Forced Browsing).

### Шаги для воспроизведения
1. Откройте веб-браузер и перейдите по прямому адресу к открытой директории приложения: `http://localhost:3000/ftp`.
2. В появившемся списке файлов найдите документ, содержащий конфиденциальную информацию о слияниях и поглощениях компании: `acquisitions.md`.
3. Кликните по названию файла, чтобы загрузить или прочесть его содержимое напрямую в окне браузера.

### Результат уязвимости
Приложение обрабатывает запрос без проверки прав доступа и предоставляет полный текст файла `acquisitions.md`. Это демонстрирует успешный обход разграничения прав и несанкционированный доступ к коммерческой тайне организации.

## 6. Название уязвимости: Отсутствие серверной проверки повторного пароля при регистрации (Repetitive Registration)
* 
* **Категория OWASP Top 10:** A05:2021-Security Misconfiguration / Improper Input Validation

### Описание
В форме регистрации новых пользователей (`/#/register`) обнаружена ошибка недостаточной валидации входных данных на стороне сервера (Improper Input Validation). Хотя клиентская часть приложения (JavaScript в браузере) требует, чтобы поля «Password» и «Repeat Password» полностью совпадали для разблокировки кнопки отправки, серверный API обрабатывает только основной параметр пароля и игнорирует проверку совпадения со вторым полем. Это позволяет обойти логику интерфейса и зарегистрировать аккаунт с несовпадающими данными.

### Шаги для воспроизведения (Взлом через Burp Suite)
1. Откройте страницу регистрации Juice Shop по адресу `http://localhost:3000/#/register`.
2. Запустите Burp Suite и включите перехват трафика (**Intercept ON**) в модуле *Proxy*.
3. Заполните форму регистрации валидными данными, указав одинаковый пароль (`password123`) в обоих полях, чтобы обойти ограничения фронтенда, и нажмите кнопку «Register».
4. В перехваченном в Burp Suite `POST`-запросе к эндпоинту `/api/Users/` найдите тело JSON-запроса.
5. Измените значение параметра `"passwordRepeat"` на любую другую строку (например, `"COMPLETELY_DIFFERENT"`), оставив исходный пароль в поле `"password"` без изменений.
6. Нажмите кнопку **Forward**, чтобы отправить измененный JSON-пакет на сервер.

### Результат уязвимости
Сервер успешно обрабатывает модифицированный JSON-запрос и возвращает ответ **HTTP/1.1 201 Created**, регистрируя учетную запись. Это доказывает полное отсутствие дублирующей проверки бизнес-логики (DRY principle) на бэкенде приложения и позволяет злоумышленникам регистрировать аккаунты в обход интерфейсных ограничений.
